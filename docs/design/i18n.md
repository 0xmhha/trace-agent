# Localization

The user interface is English by default and can be switched to Korean. The design keeps adding a language to a mechanical change.

## Frontend

- `desktop/frontend/src/i18n/core.ts` holds the locale state, `LOCALES`, `t()`, `errorText()` and Intl-based `formatNumber` / `formatDate`.
- `desktop/frontend/src/i18n/messages/<namespace>.ts` holds one namespace. Each file exports `en` and `ko`; the type of `ko` requires every English key. Components call `t('<namespace>.<key>', vars)`.
- Placeholders are written `{name}`. Plural forms use the suffixes `_one` and `_other` and are chosen with `Intl.PluralRules` when `vars.count` is a number.
- Lookup falls back to English, then to the key itself.
- The choice is stored in `localStorage` under `trace-agent.locale` and sent to the desktop process with `Bridge.SetLocale`.
- `I18nProvider` remounts the page when the locale changes, so text computed outside render is computed again.
- Dates and numbers are formatted with the locale's BCP 47 tag, never with a fixed `ko-KR`.

## Backend

- The desktop bridge rejects with stable error codes such as `usage.not_found`. The page translates them from the `errors` namespace; any other message is shown as it is.
- Native dialogs are worded in Go from the locale set with `Bridge.SetLocale`.
- Insight text is generated in Go. `usage.Query.Locale` carries the page's language to `insight.Evaluate`.
- System items of the session timeline carry a structured `system` field; `label` is an English fallback.
- Capability reasons of the trace API are English; the page translates them by capability code.

## Adding a language

1. Add a row to `LOCALES` in `core.ts`.
2. Add a column to every file in `messages/`; the compiler lists every missing key.
3. Add the code to `usage.Locales()` and a column to the Go message tables (insight rules, desktop dialogs).
