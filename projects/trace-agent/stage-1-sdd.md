## 요구사항별 검증

| 요구 | 검사와 실제 결과 |
|---|---|
| R01 두 출처 | [출처별 지원표](source-support.md)에 CLI·데스크톱 4개 경로의 직접 관찰, 이전 조사, 미확인을 기록했다. 로컬 파일과 읽기 전용 API에서 확인한 필드 범위를 표시했다. |
| R02 모델 왕복 | 두 세션 표본에는 API 요청 근거가 없다. 독립 OTel 표본에서는 C1 1회와 미연계 응답 1건을 확인했다. 해당 요청을 제거하면 응답 2건 모두 미연계다. |
| R03 도구 왕복 | 원순서, 역순, 전체 두 번, 행별 두 번 재생이 모두 기대 목록과 일치했다. 결과만 남기면 미연계로 바뀌었다. 원천 순서까지 결과 우선으로 바꿔도 ID로 원래 작업의 시도에 붙었다. 모든 Codex 시각이 같아도 호출 ID나 범위가 다르면 섞이지 않았다. |
| R04 계보·배정·종료 | 두 세션에 계보가 확인된 자식은 각각 1개다. Codex의 부모 턴·미션은 미확인이다. wait의 timed_out=true에서는 종료 0개였고, 대조 입력에 개별 자식의 완료 상태를 넣으면 종료 1개였다. Claude 자식 파일을 빼면 확인된 배정도 사라졌다. |
| R05 계획 | Codex의 계획 근거 1개에 들어 있는 두 단계가 모두 진행 중이다. Claude는 계획 미제공이다. 별도의 진행률이나 단계를 만들지 않았다. |
| R09 메타데이터 | 입력의 합성 본문·계획명·인자·결과를 바꿔도 기대 목록은 그대로였다. OTel 본문도 목록에 남지 않았다. 실제 저장기의 로그·WAL·삭제 후 재수집 검사는 후속 단계에서 한다. |
| v1.3 저장 계약 | 새 파일 DB에서 SQLite 3.53.4, user_version 13, 유일한 revision 행 (0, 0), 유일한 store_state 행 (1, 1, 0)을 확인했다. 외래 키가 켜져 있었고 foreign_key_check 0행, integrity_check 결과 ok였다. |

## 독립 검산과 재실행

2026-11-20에 GPT-6.1 Terra가 JSONL만 읽고 작업·도구·자식·모델 시도를 먼저 계산했다. 기대 파일, 재생 코드, 설계 문서는 전달하지 않았다. 위 표의 세 행, 성공·실패·불명, 미연계 위치, 동시 진행 단계 수가 재생 결과와 일치했다. 독립 검산의 대상은 합성 입력이다. 실제 클라이언트 호환성은 지원표의 범위까지 확인했다.

Node.js 24.21.0에서 저장소 루트 기준으로 실행했다. 첫 명령은 메모리 DB를 쓴다. 두 번째 명령은 비어 있는 새 디렉터리에 검증한 DB를 보관한다.

```sh
node projects/trace-agent/tests/verify.mjs
dbdir=$(mktemp -d)
node projects/trace-agent/tests/verify.mjs "$dbdir/empty.sqlite"
```

설치된 Codex의 로컬 이력을 다시 조사하려면 아래 명령을 이력이 있는 프로젝트에서 실행한다. 조회할 프로젝트 경로를 인자로 줄 수도 있다. 이 스크립트는 읽기 요청만 보내며 본문과 실제 ID를 출력하지 않는다. 알림을 관찰하는 동안 새 사건이 없으면 빈 목록을 기록한다.

```sh
node projects/trace-agent/tests/probe-codex.mjs "$PWD"
```

변경 파일은 위의 표본 3개와 기대 목록, [출처별 지원표](source-support.md), 이 SDD, [DDL](schema.sql), [재생 코드](tests/replay.mjs), [검증 명령](tests/verify.mjs), [Codex 조회 스크립트](tests/probe-codex.mjs)다. 재생 코드는 고정된 원천 순서와 범위를 가진 이 표본용이다. 원천 순서 없는 상태 갱신, 실제 어댑터의 파일 재개, 데스크톱 알림과 재시작, DB 이행·삭제는 아직 검증하지 않았다.
