# 3단계 SDD · SQLite 저장과 삭제

기준은 2단계 `733d9bc`와 데이터 계약 v1.3이다. [저장기](../../internal/store/)는 기존 [DDL](schema.sql)을 그대로 임베드한다. 보조 테이블에는 정제된 어댑터 출력, 마지막 항목 버전, 재생 차단 토큰을 저장한다. DB 파일 권한은 0600이며 SQLite 연결은 WAL, FULL 동기화, 외래 키, secure_delete를 사용한다.

## 쓰기와 재생

- **R07** 파일 스트림에서는 근거, 확인된 작업의 사실 버전과 support, 다음 완결 바이트 위치, change_scope를 한 트랜잭션에 쓴다. app-server에서는 같은 트랜잭션에 ItemVersion을 쓴다. 같은 원천 키·버전·의미 태그를 다시 받으면 기존 리비전을 유지한다. 동일 키의 내용이 충돌하거나 새 입력이 커서를 건너뛰면 저장을 거부한다.
- **R08** 조회 시 revision과 epoch를 같은 SQLite 스냅샷에서 검사한다. 삭제·동의 변경과 마지막 프레임 전송은 같은 잠금을 거친다. 최대 100건의 합성 입력을 한 리비전에 쓰는 AppendBatch도 제공한다.
- **R09** 출처·기간·세션·작업·본문 여부를 지정해 먼저 삭제 건수를 확인한다. 범위에 속한 근거나 epoch가 바뀌면 다시 미리 봐야 한다. 전체 삭제는 차단행을 쓴 뒤 support와 fact_dependency를 재귀 조회해 옛 사실 버전까지 지운다. 새 epoch에서는 남은 근거로 읽기 모델을 다시 구성한다. 키나 사건 시각이 없어서 제외할 수 없는 근거도 삭제 범위에 넣는다. 원천 파일에는 쓰지 않는다.
- 본문 저장에는 출처별 명시적 동의가 필요하다. 어댑터는 선택한 필드만 메모리에서 정제하고 저장기는 사건 시각의 동의와 현재 동의를 다시 확인한다. 지원하지 않는 형식이나 민감 패턴은 원문을 폐기한다. 본문만 삭제하면 메타데이터를 보존하고 삭제 슬롯과 차단행이 재수집을 막는다. 보존 만료는 기간과 원천 식별자를 이용해 재생을 차단한다.

## 장애 시험

동일한 합성 Claude 기록 A를 파일 어댑터로 읽었다. 시험 전용 자식 프로세스는 COMMIT 직전 또는 반환 직후에 종료 코드 79로 끝난다. 부모가 같은 DB를 다시 열어 복구 결과를 읽는다. 독립 검산은 저장기 소스와 테스트를 보지 않고 두 장애와 A 삭제 시나리오의 결과를 먼저 계산했다.

| 시험 | 기대값 | 실제 결과 |
|---|---|---|
| 커밋 전 중단 | 재시작 직후 근거·커서·사실·새 리비전 각 0개. 재생 후 각 1개 | 일치 |
| 커밋 직후 ACK 유실 | 재시작 직후 각 1개. 원천을 처음부터 다시 읽어도 각 1개 | 일치 |
| A 삭제 후 원천 재생 | A 0개, 다른 시각의 B 1개. 이전 epoch 조회 거부 | 재시작·전체 재생·파일 교체 후에도 일치. 외래 키 위반 0건 |
| 의존 사실 삭제 | A를 직접 사용한 사실과 그 입력을 쓴 중간·파생 사실까지 3개 버전 제거 | B의 사실 1개 유지. 대상 건수가 달라진 미리보기는 거부 |
| 본문만 삭제 | 철회 중 읽기 거부. 삭제 후 재동의·새 파일 세대로 재생해도 본문 복원 0건 | clean_text 0건, deleted 슬롯 1개 |
| OTel 중복·개인정보 | 모델 관찰 1건과 수집 버전이 함께 남음. 미정제 필드를 추가한 입력 거부 | 일치. 합성 본문 표식이 DB·WAL에 없음을 확인 |
| 초기화와 이행 | 빈 DB (revision 0, epoch 1). v11과 v12에서 v13으로 이행. 기존 0번 행 유지 | v12의 0번 행 유무 두 경우 통과. 기존 commit 시각 77 유지 |

[장애 입력과 시험](../../internal/store/store_test.go), [과거 버전 DDL](../../internal/store/testdata/), [2단계 어댑터 표본](fixtures/stage-1/). 과거 DDL은 study의 e6e0a55b(v11)와 f23e6696(v12)를 사용했다.

```sh
go test -race -count=1 ./internal/collect ./internal/store
go vet ./internal/collect ./internal/store
golangci-lint run --no-config --enable gosec --enable revive ./internal/collect ./internal/store
node projects/trace-agent/tests/verify.mjs
```

OS 백업이나 복제본의 물리적 삭제는 시험 범위 밖이다. SQLite API로 관찰 가능한 상태, 로컬 DB·WAL, 보존·삭제 차단과 재시작을 시험했다.
