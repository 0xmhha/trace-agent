## 기존 조사에서만 확인한 항목

- Codex의 페이지형 내부 DB에서 부모·자식 생성 관계 66건과 수신자 배열이 빈 wait 68건을 확인했다. rollout의 428파일에서 파일·종류·호출 ID가 맞은 쌍은 4,124개였다. `call_id`가 없는 출력 197건도 있었다. 이번 조사에서는 이 DB와 rollout의 건수를 다시 세지 않았다.
- Claude의 과거 가족 표본에서는 파일 안의 호출·결과 19,082쌍과 Agent 호출에서 자식까지 잇는 319쌍을 확인했다. 결과 전용 user 봉투, 혼합 블록, is_error 누락이 있었다. 이 수치는 데스크톱과 CLI로 나눌 수 없다.
- 1단계 조사 때는 훅, Claude OTel, 참여 MCP 서버, 모델 게이트웨이의 실시간 수집을 확인하지 못했다. OTel 합성 표본은 클라이언트 측 요청·응답 키의 계약만 시험한다. 실제 모델 서버나 MCP 서버의 수신 시점은 별도 근거가 필요하다. [Claude Code OTel 명세](https://code.claude.com/docs/en/monitoring-usage)
- 조사 당시의 표본 범위와 한계는 [기존 세션 조사](https://github.com/0xmhha/study/blob/26508908b43b312365463749588e82eda47f29c0/projects/trace-agent/06-session-audit.md), 설치 스키마와 지원 조건은 [자료원 문서](https://github.com/0xmhha/study/blob/26508908b43b312365463749588e82eda47f29c0/projects/trace-agent/refs.md)에 있다.

## 출시 후보의 실제 클라이언트 재검증

| 경로 | 기존·진행 중 이력 | 새 턴·재시작 | 도구·계획 또는 자식 | 판정 |
|---|---|---|---|---|
| Codex CLI 0.169.1 | 격리 프로젝트의 rollout과 읽기 전용 app-server | 같은 세션 새 턴 및 수집기 재시작 | 실제 명령과 자식 생성, 부모 2턴·자식 1턴 | 확인. [실행 결과와 명령](codex-compat.md) |
| Claude Code CLI 2.1.329 | 임시 프로젝트 폴더의 루트·자식 JSONL, 첫 턴 실행 중 파일 재개 | CLI 재시작 후 같은 세션의 새 턴, SQLite 재개 | Read·Agent·TaskCreate 3회, 자식 1개 | 확인. [실행 결과와 명령](claude-compat.md) |
| Claude Code CLI 2.1.329 / 로컬 OTel | 새로 설정한 루프백 수신기에 SDK 이벤트를 전달. 서버에서 과거 SDK 이력 조회는 지원하지 않음 | 같은 자격과 포트로 수신기 복원, 커밋 후 재전송 중복 제거 | HTTP/protobuf·JSON에서 API 본문 요청·응답 6쌍, 도구 결과 3개 | 확인. [SDK 송신 시험](otlp-compat.md) |
| Codex OTel | 수신·이력 조회 경로 미구현 | 실제 exporter 형식·재연결 미검증 | 도구·본문 검증 없음 | 미지원. 검증된 Codex 자료원은 rollout과 읽기 전용 app-server다. |
| Codex 데스크톱 | 별도 GUI에서 생성된 스레드인지 판별하지 못함 | GUI가 발행한 새 턴·재시작 미확인 | GUI의 기본 알림·도구·계획 미확인 | 제한. 선택 범위의 호환 이력만 읽음 |
| Claude Code 데스크톱 | 별도 GUI의 Code 세션 미확인 | GUI의 새 턴·재시작 미확인 | GUI의 도구·자식 미확인 | 제한. 사용자가 선택한 호환 JSONL만 읽음 |

두 CLI는 설치한 바이너리가 테스트용 루프백 모델과 대화해 새로 쓴 기록을 사용했다. 지원 범위는 확인한 클라이언트 버전과 인터페이스 조합에 한한다.
