## 세션·작업별 삭제

출처 상세에서 삭제할 기간과 자료 종류를 확인한 뒤 출처 전체, 세션 하나, 작업 하나를 선택한다. 세션·작업 후보는 해당 출처에 저장된 근거에서 소속을 확인한 ID만 50개씩 표시한다. 기존 삭제 규칙에 따라 소속이나 시각이 불명인 근거도 미리보기 건수에 포함될 수 있다. 본문만 삭제하면 근거 삭제 건수는 0이다. 최종 확인은 서버가 미리보기에서 발급한 일회용 확인값을 사용한다. 사용자가 취소하거나 범위를 바꾸면 화면에서 이 값을 폐기한다.

실제 Chrome과 임시 SQLite에 두 세션의 작업 세 개를 넣었다. 세션 한 개의 본문 두 건을 미리 본 뒤 취소하고, 작업 하나를 골라 전체 삭제했다. 최종 DB에는 나머지 두 작업의 근거가 남았다. 저장기 시험에서는 소속이 불명인 근거가 있어도 임의 ID나 다른 세션과의 조합으로는 미리보기를 발급하지 않았다. [브라우저 시험](../../desktop/frontend/test/ia.mjs) · [저장 범위 시험](../../internal/store/delete_targets_test.go)

## 재실행

저장소 루트에서 프런트엔드 의존성을 설치하고 번들을 만든 다음 브라우저 시험을 실행한다. 설치된 Chrome의 새 임시 프로필을 사용한다.

```sh
cd desktop/frontend
npm ci --no-audit --no-fund
npm run build
cd ..
TRACE_IA_BROWSER=1 go test -race -count=1 -v -run '^TestDesktopIA$' .
```

이 시험에서 네이티브 파일 선택 창과 운영 계정의 권한 저장소는 사용하지 않았다. 설치물 빌드와 성능 측정은 8단계의 별도 검증 대상이다.
