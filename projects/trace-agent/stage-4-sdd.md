# 4단계 SDD · 사실과 통계 조회

데이터 계약 v1.3, SQLite user_version 13, 요구사항 R02~R06과 R11을 적용했다. 공개 조회는 저장기가 확인한 revision과 epoch의 근거에서 시작한다. 원천 필드가 담긴 레코드에는 Codex와 Claude 해석기를 적용하고, 명시적으로 게시한 사실은 해당 revision까지의 최신 버전을 선택한다. [기준판 구현 인계](https://github.com/0xmhha/study/blob/26508908b43b312365463749588e82eda47f29c0/projects/trace-agent/07-implementation-handoff.md)

## 조회와 근거

- R02·R03. Codex 프로필 안의 스레드·턴, Claude 세션 안의 외부 사용자 프롬프트와 레코드 부모 관계로 작업을 식별한다. Claude 위임은 Agent 호출, 해당 결과 블록과 자식 기록의 agentId를 연결한다. 부모 스레드만 알려진 자식은 독립 identity로 남는다. Codex 계획은 버전과 단계별 상태를 유지하므로 동시에 진행 중인 단계가 모두 나타난다.
- R04·R05. 호출 키를 스트림과 작업 안에서 해석한다. 명시적인 성공·오류 코드, 시작 관찰, 유효 기한이 남은 실행 중 보고와 종료를 구분한다. 도구 결과만 수신하면 종료와 성패 불명으로 표시한다. Claude OTel의 식별된 요청·성공 응답은 해당 출처 안에서만 한 번 집계한다. 서버가 다른 동명 MCP 도구는 서로 다른 모듈이다.
- R06. 시도의 시작이 선택 기간에 속해야 통계에 포함된다. 실패율의 분모는 성공·오류를 판별할 수 있는 시도 수다. 계측값과 동일 시계에서 확인한 양끝 시각의 차이를 각각 집계한다. p95는 순위 올림을 사용한다. 각 측정값은 표본의 작업·모듈·기간·측정 방식을 전달한다.
- R11. 공개 행에서 근거 ID로 원천과 관찰 시각을 확인한다. 본문이 필요한 경로에서는 해당 블록 위치만 전송 계층에 알려 준다. 원문은 읽기 모델에 넣지 않는다.
- 사실 게시와 근거·사실 간 의존성 기록은 하나의 트랜잭션이다. 출처에 존재하는 근거 ID만 받는다. 삭제는 영향을 받은 버전, 같은 사실의 더 오래된 버전, 이를 사용한 하위 사실을 함께 지운다.
