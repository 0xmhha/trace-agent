## 동작

- **R06** 카드의 표본 토큰은 시점, 실제 조회 기간, 출처, 클라이언트, 작업과 집계 조건에 묶인다. 같은 토큰으로 읽은 목록·상세에서 다른 표본의 ID를 지정하면 `data: null`과 `NOT_FOUND`를 돌려준다. 다음 페이지 커서는 같은 시점·정렬·크기·표본에서만 쓴다. 출처 모델 시도는 `sourceScope`로 고른 단일 출처에서 읽는다.
- **R07** 등록만 끝난 출처도 해당 리비전의 출처 설정에서 읽는다. 출처 목록은 이력을 재구성하지 않는다. 현재 건강은 따로 확인한 출처만 `currentStatus`에 넣는다. 출처 상태 점검 전에는 건강을 추정하지 않는다.
- **R08** 초기 스냅샷의 시점 이후 변경을 100ms 주기로 확인한다. 같은 시점은 한 번만 보내고 여러 커밋은 직전에 보낸 시점을 base로 하여 전체 화면 하나로 교체한다. 고정 화면은 epoch 변경을 감시한다. 시점·필터·재생 바닥·프레임 크기를 검사하고 복구할 수 없는 구독에는 Reset과 complete를 보낸다. FOLLOW_END의 끝은 마지막 커밋 시각에 1ms를 더한 값과 기존 끝 중 늦은 쪽이다.
- **R09** 서버는 임의의 루프백 포트에서 WebView의 Origin, Host와 `graphql-transport-ws`를 검사한다. 첫 `connection_init.payload.ticket`는 네이티브에서 발급한 일회용 30초 티켓이다. 연결당 연산 16개, 동시 연결 8개, 입력 64KiB, 출력 1MiB로 제한한다. 설정 변경에는 관리 권한이 필요하다. 삭제 확인값은 같은 연결의 미리보기·범위·epoch와 1분 만료 시간에 묶인다.
- 본문은 상세의 근거와 원천 블록 순서로 조회한다. 본문을 보관하는 화면 캐시는 없다. 저장기에서 현재 동의를 확인한 뒤 최종 소켓 쓰기를 개인정보 정책 변경과 같은 잠금 안에서 수행한다. 쓰기 제한 시간은 1초다. epoch가 바뀌면 다시 조회해야 하며, 제한 시간 내 새 epoch 확인을 보내지 않은 연결을 닫는다. 한 화면의 본문 합계는 UTF-8 128KiB이며 저장 시 잘림과 표시 시 잘림을 구별한다.
