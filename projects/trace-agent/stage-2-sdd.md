# 2단계 SDD · 수집 어댑터

기준은 데이터 계약 v1.3과 1단계 커밋 `6c420c0`이다. Go 패키지 [internal/collect](../../internal/collect)가 사용자가 선택한 출처에서 근거를 읽어 저장기에 넘긴다. 이 단계의 출력은 원천 위치와 메타데이터다. 고유 작업·시도·자식 수는 1단계 기대 목록과 대조해 연결에 필요한 키가 살아 있는지 확인했다. [구현 인계](https://github.com/0xmhha/study/blob/26508908b43b312365463749588e82eda47f29c0/projects/trace-agent/07-implementation-handoff.md)

## 입력과 출력

| 입력 | 진입점과 읽는 범위 | 출력과 재개 기준 |
|---|---|---|
| Codex app-server v2 | `CollectLocalCodex`가 설치된 CLI와 stdio로 통신한다. `CollectApp`은 호출자가 연 연결을 받는다. 지정 디렉터리의 일반·보관 스레드와 턴·항목 페이지를 읽는다. 항목 조회 메서드가 없으면 턴별 전체 항목으로 재시도한다. | 이력과 알림은 같은 출처·스레드·턴·항목 ID를 사용한다. 시작과 종료 근거, 관찰한 시각, 출처에서 제공한 항목 시각을 구분한다. Follow 모드에서 새 알림을 처리하면서 최근 턴을 직렬 폴링한다. 이전에 본 첫 턴까지 다시 읽으므로 폴링 사이에 생긴 여러 턴도 회수한다. |
| Codex rollout과 Claude Code 루트·자식 JSONL | `ReadFile`에 선택한 `os.Root`, 상대 경로, 마지막으로 저장한 커서를 준다. 한 번의 읽기는 처음 확인한 파일 크기까지다. | 파일별 바이트 위치와 세대를 사용한다. 줄바꿈까지 읽고 정제한 뒤 저장기 콜백에 근거와 다음 커서를 함께 넘긴다. 콜백이 성공한 경계만 반환한다. 교체·축소 또는 직전 경계의 바이트 변경을 발견하면 공백 사유와 새 세대의 0번 경계를 먼저 넘긴다. |
| Claude OTel 이벤트 속성 | `Project`는 출처, 스트림, 세대와 원천 위치가 정해진 이벤트 한 건을 받는다. JSONL에 저장한 속성은 `ReadFile`로도 읽을 수 있다. | 요청·응답 방향, 모델과 요청 키, 메시지 키를 남긴다. 모델 요청에 연결할 키가 없는 응답도 독립 근거로 보존한다. |

`Evidence`에는 출처·프로필·스트림·세대, 레코드·버전 키, 정제한 의미 필드의 태그, 관찰자, 어댑터 버전, 관찰 시각, 정제 결과가 들어 있다. 클라이언트 버전은 확인된 숫자 버전을 사용한다. 원천 ID와 경로는 설치별 비밀 키로 HMAC 처리한다. 필드 이름과 식별 범위가 보존되므로 저장기는 같은 프로필의 명시적 연결 키를 대조할 수 있다. 승인 목록 밖의 도구명도 불투명한 키로 바꾼다.

3단계 저장기는 파일의 `FileCommit`에서 근거와 커서를 한 트랜잭션에 저장한다. app-server의 `AppSink`는 마지막으로 확정한 `ItemVersion`을 조회하고 새 버전과 근거를 함께 커밋한다. 한 출처에 연결 하나를 직렬로 사용한다. 파일 재시작에는 같은 설치 키와 저장된 커서가 필요하다. 페이지형 이력은 새 연결에서 다시 읽고 저장된 버전과 대조한다. 안정적인 사건 ID가 없는 계획 알림은 연결 세대 안의 관찰 순서로 남긴다.

## 재실행

저장소 루트에서 실행한다. 실측 환경은 Go 1.26.11, Node.js 24.21.0, macOS arm64다. Go 모듈은 표준 라이브러리만 사용한다.

```sh
go test -race -count=1 ./...
go vet ./...
golangci-lint run --no-config --enable gosec --enable revive ./...
go test -run '^$' -fuzz '^FuzzProjection$' -fuzztime=3s -parallel=2 ./internal/collect
node projects/trace-agent/tests/verify.mjs
```

2026-11-20에 race 검사를 포함해 전체 Go 시험을 세 번 통과했다. go vet과 위 린트에서 지적 사항은 0건이었다. 3초 퍼즈 시험과 1단계 SQLite·표본 회귀 시험도 통과했다.

기본 시험은 합성 자료를 사용한다. 실제 Codex에서 이 작업 디렉터리의 이력을 확인할 때만 다음 명령을 실행한다. 출력에는 항목 종류와 건수만 들어간다. 작업 중인 세션의 수치는 실행 시점에 따라 달라진다.

```sh
TRACE_TEST_CODEX_DIRECTORY="$PWD" go test -count=1 -run '^TestLocalCodex$' -v ./internal/collect
```

## 검증이 남은 범위

- 합성 서버에서 항목 알림과 새 턴의 폴링을, 임시 파일에서 기록 도중의 재개와 파일 교체를 시험했다. 실제 데스크톱이 보낸 알림 수신과 실행 중인 Claude Code 세션의 파일 재개는 아직 확인하지 않았다.
- 이 단계는 동의 전 메타데이터 경로를 제공한다. 동의한 본문의 저장·철회, SQLite에 근거와 커서를 함께 커밋한 직후의 프로세스 중단, WAL 정제는 후속 단계에서 검증한다.
- Claude OTel은 1단계의 이벤트 속성 형식을 검증했다. 실제 OTLP 리스너, 훅 설치, 모델 서버와 MCP 서버 쪽 수신 기록은 시험하지 않았다. 파일 형식이 제공하지 않는 작업 배정이나 API 요청 키는 미연계로 남는다.


## Codex CLI의 로컬 OTel

`codex-otel`은 사용자가 선택한 프로필의 독립 출처다. 등록한 루프백 포트와 인증 토큰으로 OTLP/HTTP Logs 묶음을 받고, 기존 OTLP 수신기의 인증·입력 제한·커밋 절차를 재사용한다. 발신 SDK의 나노초 관찰 시각과 밀리초 발생 시각을 구분한다. 클라이언트가 보고한 API 시도 번호에는 모델 왕복을 식별할 키가 없다. 읽기 모델은 해당 근거를 출처의 미연계 목록에 넣는다. 화면의 단건 조회와 실시간 조회는 같은 숫자·불리언 필드를 제공한다. 정제한 사용자 입력은 사건 시점과 조회 시점의 동의가 유효한 경우에만 본문 슬롯에서 읽는다. [지원 필드와 설치본 검증](codex-compat.md#로컬-otel-수신)
